# Анатомічна мапа та каталог вправ

## Мета

Перетворити бібліотеку вправ на керований каталог із точною анатомічною
розміткою. Каталог має пояснювати, які м'язи задіює вправа, давати змогу
фільтрувати вправи через мапу тіла й пізніше живити персональну статистику
навантаження.

## Узгоджені продуктові рішення

- Перший каталог охоплює 80–100 поширених силових вправ українською мовою.
- Моделюємо лише треновані м'язи: приблизно 18–20 функціональних зон,
  наближених до наявних SVG.
- Ліва і права симетричні зони є одним логічним м'язом. Поточні сети не
  зберігають сторону, тому мапа підсвічує обидві сторони одночасно.
- Передню поверхню стегна розділено на зовнішню частину квадрицепса
  (`quadriceps`) і прямий м'яз стегна (`rectus_femoris`), щоб центральна зона
  біля паху не вмикалась разом із зовнішнім контуром.
- Вправа може мати кілька основних м'язів. Для кожного зв'язку з м'язом
  зберігається статична оцінка залучення від `1` до `10`.
- `8–10` — основні м'язи, `4–7` — додаткові, `1–3` — легке залучення або
  стабілізація. Деталі вправи показують усі зв'язки; фільтр за м'язом показує
  лише вправи з оцінкою від `4`, відсортовані за спаданням оцінки.
- Оцінка описує вправу, а не конкретний сет. Вона не є медично точним
  розподілом тоннажу.
- Історичні тренування завжди використовують актуальну розмітку каталогу:
  виправлення асоціації вправи автоматично уточнює минулу статистику.
- Шість широких груп (`chest`, `back`, `legs`, `shoulders`, `arms`, `core`)
  лишаються швидкими фільтрами та підписами. Вони мають походити від
  основного анатомічного м'яза, а не бути другим незалежним джерелом правди.

## Дані та синхронізація

Схема створюється міграціями. Вміст системного каталогу не зберігається в
міграціях: він синхронізується так само, як конфігурація ачівок.

Заплановані сутності:

| Сутність                | Призначення                                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `anatomical_muscles`    | Канонічні ключі та українські назви м'язів, широка група й порядок відображення.               |
| `exercise_muscles`      | Зв'язок вправи з м'язом і `activation_score` від `1` до `10`; унікальний для пари вправа–м'яз. |
| `exercises.catalog_key` | Стабільний ключ системної вправи для upsert без зміни її UUID, сетів і вподобань.              |
| `exercises.is_active`   | Приховує застарілу системну вправу з каталогу без видалення її історії.                        |

Зв'язки `exercise_muscles.exercise_id` та `exercise_muscles.muscle_key` мають
бути проіндексовані. Для власних вправ RLS дозволяє читати й змінювати лише
зв'язки до вправ поточного користувача; для системних — лише читання.

SVG-id не є ключем БД. Окремий фронтенд-мапінг зіставляє канонічний ключ
м'яза з його лівими й правими елементами у `front-organized.svg` та
`back-organized.svg`.

Заплановані джерело даних і команда синхронізації:

- `scripts/exercise-catalog-config.mjs` — список м'язів, системних вправ і їх
  оцінок залучення;
- `scripts/sync-exercise-catalog.mjs` — валідація й upsert через service role;
- `npm run db:sync-exercises` — команда для запуску синхронізації.

Синхронізація не торкається власних вправ. Відсутні у конфігурації системні
вправи деактивуються, а не видаляються.

## Інтерфейс — етап 1

- Бібліотека зберігає текстовий пошук, фільтри за широкою групою та
  обладнанням.
- Велика інтерактивна мапа з перемикачем **Перед / Спина** обирає один м'яз.
  Повторний тап знімає фільтр; мультивибір не входить у першу версію.
- Картка в бібліотеці відкриває деталі вправи. У виборі вправи під час
  тренування тап одразу додає вправу, а кнопка `i` відкриває деталі.
- Деталі вправи містять компактну фронтальну й задню мапу, секції
  «Основні» / «Додаткові» та шкалу `10/10`, `7/10` тощо.
- Створення власної вправи вимагає основний м'яз і дозволяє додати інші з
  оцінкою залучення.
- Вкладки з технікою, відео та коучингом не входять у етап 1. У майбутньому
  для них додається окрема сутність на зразок `exercise_guides`.

## Аналітика — етап 2

- У деталях тренування показується мапа м'язів, задіяних у цій сесії.
- На сторінці «Прогрес» показується мапа за обраний період.
- Для обох мап використовується **бал стимулу**: кожен завершений підхід
  додає м'язу `activation_score`. Це включає вправи з власною вагою та вправи
  на час, які сьогодні не мають тоннажу в кілограмах.
- Бал стимулу не підписується як кілограми; поточний тоннаж у кг лишається
  окремою метрикою.

## Порядок реалізації

1. Міграція схеми, індекси, RLS і збереження сумісності з чинними сетами та
   вподобаннями.
2. Конфігурація й скрипт синхронізації системного каталогу, включно з
   розміткою поточних вправ.
3. Спільний React-компонент анатомічної мапи й переробка бібліотеки, вибору
   вправ, деталей та форми власної вправи.
4. Після перевірки каталогу — RPC і UI для мап тренування та прогресу.
