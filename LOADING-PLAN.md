# Завантаження сторінок PRGRSS

## План

- [x] Видимий старт до запуску React та окремий стан перевірки сесії з повторною спробою.
- [x] Стала оболонка після авторизації, каркаси даних і повідомлення про повільну або відсутню мережу.
- [x] Явні помилки й недоступні записи; наявні дані зберігаються під час фонового оновлення.
- [x] Ізольований кеш запитів для кожного акаунта, попереднє завантаження без блокування переходів.
- [x] Історія підходів завантажується окремо й не перезаписує введення.
- [x] Перевірки сценаріїв, типів, lint і production build.

## Крайові випадки та критерії

| Випадок                                     | Очікувана поведінка                                                                                 |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Повільний JavaScript або перевірка сесії    | Видимий стартовий екран, без особистих даних до підтвердження сесії.                                |
| Помилка, відхилений або завислий getSession | Зрозуміле повідомлення та повторна спроба; пізня стара відповідь не скасовує нову сесію.            |
| React StrictMode / розмонтування            | Підписки й таймери очищаються, застарілі відповіді ігноруються.                                     |
| Перший запит / відсутність мережі           | Каркас із поясненням очікування; пауза запиту не означає порожній результат.                        |
| Повторний перехід / фоновий refetch         | Кешований контент залишається; помилка оновлення не приховує його.                                  |
| Запит завершився помилкою                   | Повторна спроба замість нескінченного skeleton або порожнього екрана.                               |
| Видалене чи недоступне тренування           | Окреме повідомлення, без навігації під час render.                                                  |
| Швидка зміна вправи                         | Попередні дані іншої вправи не показуються під новим URL.                                           |
| Перемикання акаунта / вихід                 | Новий QueryClient та нове дерево маршруту; кеш попереднього акаунта не використовується.            |
| Prefetch не вдався / немає мережі           | Перехід не блокується; сторінка обробляє власний стан запиту.                                       |
| Історія підходів прийшла пізніше            | Змінюються підказки й початкові значення лише майбутніх доданих вправ; поточні підходи залишаються. |
| Порожня бібліотека чи статистика            | Змістовний порожній стан, а не повідомлення про мережеву помилку.                                   |
| Reduced motion / скринрідер                 | Декоративні skeleton приховані, є текстовий статус, анімацію можна вимкнути.                        |

Не додаємо штучних мінімальних затримок чи offline-first сховища. Розміри каркасів наближені до контенту, без обіцянки точного часу завершення.

## Реалізація

- Стартова розмітка є вже в HTML. Перевірка сесії обмежена 15 секундами, із захистом від застарілих відповідей і повторною спробою.
- Дані основних сторінок читаються з обмеженням очікування 20 секунд. Через 12 секунд очікування з’являється пояснення. Timeout не запускає автоматичний повтор, щоб не множити завислі запити. Звичайні помилки мають одну автоматичну повторну спробу.
- Обмеження очікування не скасовує сам HTTP-запит, якщо його API не підтримує AbortSignal. Воно відхиляє пізній результат для кешу. Мутації цим механізмом не обмежуються, бо результат запису на сервері міг уже застосуватися.
- Каркаси мають варіанти для списку, показників, форми й карток. Текстовий статус розміщений поза `aria-busy`; декоративні елементи приховані від скринрідера. Для skeleton і верхньої смужки враховано reduced motion.
- Prefetch використовує ті самі query options, що й сторінки. Він не очікується маршрутом. Статистику й досягнення винесено в окремі JS chunks; невдале завантаження коду має екран повторного відкриття.
- Новий акаунт отримує інший QueryClient; під час розмонтування скасовуються запити попереднього. Тривалість зберігання неактивного кешу в пам’яті — 30 хвилин. Це не додає персистентного offline-кешу й не змінює формат локальних чернеток тренувань.

## Результати перевірки

- `npm run test:loading`: 11 тестів пройшли, зокрема timeout, пізні відповіді, зміна акаунта, фонові помилки й offline/reconnect.
- `npm run test:workout`: 18 тестів пройшли, включно зі збереженням уже введеного підходу після появи історії для наступної вправи.
- `npm run test:calendar`: 10 тестів пройшли.
- `npm run ci`: TypeScript, ESLint і production build пройшли. Залишаються 5 наявних попереджень Fast Refresh та попередження про великий основний JS chunk.
- Основний JS chunk скоротився приблизно з 1 443 кБ до 1 038 кБ (gzip: з 425 до 310 кБ). Це результат розбиття коду, а не виміряне скорочення часу мережевого запиту. Загальний обсяг PWA precache не зменшився.
- У браузері підтверджено послідовність «каркас головної з навігацією → завантажена головна», а також наявність заголовка, фільтрів і навігації під час завантаження статистики. Подальша автоматизація браузера знову завершилася timeout; візуальні стани помилок і offline перевірені не всі. Відповідні сценарії сесії та запитів перевірені автоматичними тестами.
