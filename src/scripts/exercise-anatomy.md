# Відповідність вправ анатомії

Основний каталог — `exercise-catalog-config.mjs`. Перевірені старі системні назви — `exercise-anatomy-backfill.mjs`. Автоматична розмітка застосовується тільки до системних записів (`is_custom = false`, `user_id is null`). Для власних вправ користувач сам обирає основний і додаткові м’язи у формі створення; синхронізація їх не змінює й не пропонує для автоматичного зіставлення.

Перевірка без запису:

```sh
npm run db:backfill-exercise-anatomy
```

Заповнення пропусків у підключеному Supabase:

```sh
npm run db:backfill-exercise-anatomy -- --apply
```

URL та серверний ключ читаються з `.env.local`. Ключ залишається в серверному скрипті й не потрапляє до клієнтського коду. Команда спочатку додає відсутні записи довідника м’язів, потім пакет прив’язок. У разі помилки можна повторити запуск: наявні прив’язки не перезаписуються. ID, назви, активність вправ і підходи тренувань зберігаються. Тригер БД оновлює загальну групу м’язів відповідно до доданої розмітки.

Порівняння враховує повну назву та обладнання, ігнорує регістр і зайві пробіли. Для відомих старих назв явно задано профіль. Невідомі або неоднозначні назви виводяться в `unresolved`; вгадування за словами чи загальною групою м’язів немає. Повна синхронізація `npm run db:sync-exercises` теж запускає заповнення пропусків після оновлення основного каталогу.

Оцінки 1–10 є умовними значеннями каталогу для виділення основних і додаткових м’язів, а не вимірами EMG чи персонального навантаження. Для старих системних вправ повторно використовуються наявні профілі рухів.

Після заповнення 30 жовтня 2026 року всі 100 системних записів мають розмітку (усі 50 вправ початкового каталогу включно). Додано 53 прив’язки для 18 старих системних записів і відсутній довідниковий запис прямого м’яза стегна. Автоматично додані прив’язки для 6 власних вправ відкочено після уточнення правила користувачем; власні вправи залишаються для ручного вибору анатомії.

Після оновлення даних перезавантаж сторінку: каталог у React Query кешується на 30 хвилин.
